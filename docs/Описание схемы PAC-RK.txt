Программно-Аппаратный Комплекс управления Ректификационной Колонной (PAC-RK) - Описание принципиальной электрической схемы
1. Общая архитектура
Комплекс представляет собой модульное устройство, построенное на двух микроконтроллерах (МК) Arduino Nano / ATmega328P. Схема разделена на две гальванически развязанные части: «горячую» (силовая часть, работающая с напряжением 220В) и «холодную» (управляющая и измерительная часть, работающая с низковольтными сигналами). Ключевой элемент развязки — микросхема ADUM1250.

Основные функциональные блоки:

Силовой блок (регулятор напряжения) — управление нагревом куба.

Блок управления — сердце системы, управляет насосом, опрашивает датчики, обеспечивает интерфейс.

Блок насоса — управление шаговым двигателем для отбора/дозирования.

Блок индикации и управления — два OLED дисплея и два энкодера.

Интерфейсный блок — связь с ПК по USB и Bluetooth.

2. Детальный разбор узлов схемы (по файлам проекта)
2.1. Левая часть схемы: Силовой регулятор (220В)
Эта часть отвечает за стабилизацию и регулировку мощности на нагревательном элементе (ТЭНе).

Питание микроконтроллера (М2): Использует бестрансформаторный импульсный преобразователь 220АС/5DC для питания этой части схемы. Ключевой момент: эти 5В никогда не должны контактировать с «холодной» землей.

Измерение напряжения (датчик нуля и контроля напряжения): Напряжение сети 220В поступает через R5, R11; напряжение нагрузки через R1, R2. Эти резисторы формируют гальваническую развязку по напряжению. Сигнал подается на TL431, который работает как источник опорного напряжения, и далее на АЦП Ардуины. Это критически важный узел для стабильной работы. В прошивке regulator.hex реализован алгоритм фазового управления.

Силовой ключ: Основной элемент — оптопара MOC3063 (или MOC3052) с детектором нуля и мощный симистор BTA41-600 или аналогичный.

Режим разгона: Используется дополнительное реле (на схеме не показано, но упоминается в спецификации и обсуждениях), которое при активации режима разгона шунтирует симистор, подавая на ТЭН полное сетевое напряжение.

Аварийный вход (DA3): Вход, предназначенный для внешнего датчика. Нормально замкнут. Разрыв цепи приводит к «аварийному выключению» — блоку нагрева, остановке отбора и включению сигнализации.

2.2. Правая часть схемы: Управляющий контроллер
Это «мозг» системы, предположительно второй контроллер (DD2 - Arduino Nano). Он отвечает за логику работы.

Датчики температуры (DS18B20): Использует 4 независимых канала (разъемы XS1). Каждый датчик подключен к отдельной ноге Ардуины. Это позволяет системе продолжать работу при выходе из строя одного датчика и упрощает идентификацию (датчик №1 — всегда на порту А0). Опрос происходит по протоколу 1-Wire.

Управление шаговым двигателем: В схеме используются выходы D8-D11 для подачи управляющих сигналов на драйвер шагового двигателя. В спецификации рекомендуется использовать "тихие" драйверы TMC2208/9.

Дисплеи (OLED): Предусмотрено два дисплея. Большой (M5) 2.42" – на контроллере SSD1309, подключен по шине I2C (SDA, SCL). Маленький (M1) 0.96" – также на SSD1306/1309, подключен через отдельный разъем.

Управляемые выходы (DD2, ноги D8-D11): На схеме показаны как управляемые выходы. Они могут быть программно использованы для включения дополнительных устройств (например, клапана НУО, сигнализации) при срабатывании определенных температурных порогов.

2.3. Связь и интерфейсы
Гальваническая развязка: Микросхема ADUM1250 используется для изоляции шины I2C между двумя МК. Без нее подача питания на USB порт компьютера для прошивки или управления через monitor.exe может привести к выходу из строя ПК. Это огромная проблема безопасности, которую необходимо решать в прошивке.

Bluetooth: Модуль HC-05 (или JDY-33) подключен через цепочку цифровых транзисторов DTA114 и DTC114. Эта цепочка реализует «монтажное ИЛИ» для линии RX, позволяя управлять устройством и по Bluetooth, и по USB шнурку без конфликтов. Без этих транзисторов, как поясняет автор, многие Bluetooth-модули не в состоянии «продавить» линию RX Ардуины, что приводит к невозможности управления с ПК по Bluetooth, хотя мониторинг может работать.

Связь с ПК: По USB через встроенный порт Ардуины напрямую используется для прошивки и управления. Рекомендовано использовать USB-изолятор (например, ADUM3160) для полной защиты ПК.

3. Алгоритм работы (по прошивке CONTROL.hex)
Программа, залитая в этот микроконтроллер, выполняет следующие действия в бесконечном цикле:

Чтение параметров: Опрашивает все датчики температуры и считывает состояние энкодеров.

Отображение: Обновляет графику на дисплеях.

Логика управления: Проверяет для каждого датчика, не вышли ли показания за установленный порог.

Если порог превышен: Выполняет заданное действие (остановка отбора, выключение нагрева, подача звукового сигнала).

Управление насосом: Формирует импульсную последовательность на выходах D8-D11 для обеспечения заданной скорости отбора. Учитывает режим дозатора (автостоп при достижении заданного объема).

Обработка команд от ПК/Bluetooth: Анализирует данные, поступающие по UART, и исполняет команды (изменение скорости отбора, установка порогов температуры и т.д.).

Обмен с силовым регулятором: Отправляет команды на I2C-шину для управления нагревом.

4. Ключевые компоненты (из bill-of-materials.pdf)
Микроконтроллеры: 2x Arduino Nano (или ATmega328P на плате) — основа работы всей системы. Проблемы с зависаниями часто связаны именно с некачественными китайскими клонами.

Драйвер шагового двигателя: TMC2208/TMC2209 — ключ к тихой работе насоса.

Развязка (изоляция): ADUM1250 — ключ к безопасности при подключении к ПК. Замена на ISO1540 также возможна.

Энкодеры: EC11 — для ручного управления.

Симистор: BTA41-600 — силовой ключ для управления нагревом.

5. Рекомендации для разработки и доработки
Для совершенствования прошивок и добавления нового функционала при работе над схемой и ее программным обеспечением следует обратить внимание на следующие моменты:

Надежность питания: Как показывает форум, основная причина зависаний — нестабильное питание Ардуины. Вместо импульсного преобразователя, греющегося линейного стабилизатора или некачественного БП 12В можно использовать более качественный DC-DC преобразователь для правой части схемы и добавить LC-фильтры по линиям питания (на входе питания и для М2). Это кардинально повысит стабильность.

Изолятор USB: Настоятельно рекомендовать пользователям применять USB-изолятор (например, ADUM3160) между ПК и комплексом для защиты от пробоя через гальванически развязанные интерфейсы.

Алгоритм «термостат»: Добавить программный гистерезис для работы в режиме «термостат». Это позволит использовать комплекс для поддержания температуры браги или осахаривания зерна без доработки аппаратной части.

Декремент отбора: Реализовать алгоритм плавного снижения скорости отбора по мере падения температуры в кубе (или по давлению). Это позволит «выжать» максимум спирта без риска «проскока» в хвосты.

Контроль давления (новый функционал): Для добавления датчика давления необходимо:

Выбрать совместимый датчик (например, XGZP6857D с I2C-интерфейсом).

Адаптировать прошивку CONTROL.hex для чтения данных с этого датчика по шине I2C (путем изменения адреса устройства и добавления соответствующей библиотеки).

Модифицировать monitor.exe (или его будущий веб-аналог) для отображения и логирования нового параметра.

Переход на ESP32: Как было детально проанализировано, это самый серьезный апгрейд. Он решит проблемы интерфейса, платформонезависимости и производительности. Схема работы для перехода на ESP32 v2.0:

Единый контроллер заменяет оба МК.

Прямое управление симистором через внешнее прерывание и аппаратные таймеры.

Хостинг веб-интерфейса на самом ESP32, что открывает доступ с любого устройства через браузер.

Отказ от USB-порта для управления, использование Wi-Fi для удаленного доступа.

Это потребует полной переработки платы.
